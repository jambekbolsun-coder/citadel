# Решения

1. **Один Next.js-проект** для сайта и приложения: `/` публичный, `/app/*` закрыт proxy + RLS.
2. **Права в БД.** Все бизнес-правила — security definer функции с `has_perm`, таблицы под RLS; клиенту доступен только publishable key. Сервисный ключ не используется вовсе.
3. **Первый владелец** назначается через `/setup` + `claim_first_owner` (работает только пока владельца нет). Остальные — только через приглашения.
4. **PIN** проверяется на сервере (bcrypt в `device_pins`, 3 ошибки — пауза 1 мин, 5 — удаление PIN и выход). Это экран блокировки доверенного сеанса, а не способ входа.
5. **Деньги** — bigint в минимальных единицах; суммы вводятся строкой и парсятся без float.
6. **План-факт** вычисляется представлением из plan_items/content_items/placements/story_daily_plans — нет хранимых счётчиков, нет двойного подсчёта.
7. **Тарифы** версионируются; проект хранит `tariff_version_id` и снимок в `project_contracts.tariff_snapshot`. Поправки — `project_amendments` с основанием.
8. **Сторис**: метод фиксируется в проекте (`fixed_per_period` или `four_each_calendar_day`); при 4/день показывается разница с договорным числом.
9. **Секреты** соцсетей — Supabase Vault; просмотр требует входа паролем ≤15 мин (claim `amr` в JWT) и логируется.
10. **Нормативы времени** по умолчанию пустые — система честно пишет «ёмкость не рассчитана».
11. **Web Push**: уведомление пишется в `notifications`, триггер через pg_net будит edge-функцию `push-dispatch` (секрет вызова и ключи VAPID — в Vault, ключи созданы функцией и не покидают сервер). Функция шифрует и отправляет, мёртвые подписки (404/410) удаляет, повторяет до 5 раз, старше суток не шлёт. Входящие + realtime остаются основным каналом.
14. **Серии повторов** разворачиваются в отдельные задачи/съёмки при создании (≤ 60), а не «виртуально»: каждую можно перенести, назначить и закрыть отдельно, план-факт и история работают как обычно. Исполнителю — одно уведомление на серию.
15. **Перетаскивание в календаре** вызывает те же RPC переноса (`task_reschedule`, `shoot_reschedule`, `content_reschedule`) с обязательной причиной — права и история не обходятся.
12. **cacheComponents выключен** — приложение полностью динамическое и персональное, кэширование приватных ответов запрещено (`Cache-Control: private, no-store` для /app, SW не кэширует HTML/API).
13. **Дизайн**: тёмно-зелёная палитра и формы референса kadr-drab (экран входа), красный — только брендинг и акценты. Внутренние экраны референса закрыты авторизацией — точность сравнения ожидает скриншотов от владельца.
18. **Мобильная навигация**: 5 позиций внизу, 4-я — раздел по роли (`resolveWorkTab`), сотрудник может закрепить другой доступный раздел (cookie на устройстве, не в БД). Уведомления — в шапке. Все прочие разделы — из настроек и главной.
19. **Регион функций `dub1`** — рядом с Supabase `eu-west-1`; при `iad1` каждый запрос к БД пересекал Атлантику, страница делает 4–5 последовательных запросов.
20. **Тёмная тема — тёмно-синяя** (референс экрана настроек), светлая — нейтральная; красный — центральная кнопка и главные действия.
