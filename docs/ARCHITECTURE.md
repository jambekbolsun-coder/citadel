# Архитектура

## Слои
```
Браузер / PWA (service worker: только статика + офлайн-страница)
   │  HTTPS, cookies сессии Supabase (httpOnly через @supabase/ssr)
Next.js на Vercel
   ├─ src/proxy.ts — обновление сессии, закрытие /app/* для неавторизованных
   ├─ Server Components — чтение данных от имени пользователя (RLS)
   └─ Server Actions — мутации через RPC/таблицы (RLS + проверки в функциях)
Supabase
   ├─ Postgres: таблицы с RLS, security definer функции бизнес-правил, представления план-факт
   ├─ Auth: email+пароль, подтверждение email, восстановление пароля
   ├─ Realtime: notifications, leads (фильтрация RLS)
   ├─ Storage: avatars (public), files / finance (private, политики по проекту/правам), site (public)
   ├─ Vault: пароли соцсетей клиентов (project_secrets → vault.secrets)
   └─ pg_cron: run_reminders() каждые 15 мин (съёмки 24ч/2ч, просрочки, эскалация лидов, счета, зарплаты, проверки)
```

В браузер не передаётся ни один серверный ключ: используется только publishable key, все права — RLS.

## Пять функциональных модулей
1. **Учётные записи и PWA** — `/setup` (первый владелец), QR-приглашения (`create_invite` → хэш токена, TTL, отзыв/перевыпуск), `/invite/[token]`, утверждение владельцем, PIN устройства (bcrypt на сервере, лимит попыток), сеансы.
2. **Сайт и продажи** — CMS (`site_blocks` draft/published + `site_versions`), лид-форма (`submit_lead`: honeypot, rate-limit по IP-хэшу/телефону/глобально, идемпотентность, уведомления в той же транзакции), CRM-воронка, клиенты, тарифы с версиями.
3. **Производство** — проекты (мастер из 4 шагов), договор (`project_contracts` со снимком тарифа), периоды, план (`plan_items`), материалы (`content_items` со state machine), размещения, сторис по дням, задачи, съёмки с участниками/подтверждениями/конфликтами, реклама, доступы (Vault).
4. **Календарь, контроль, отчёты** — год/месяц/неделя/день, фильтры, загрузка; ежедневные проверки администратора; план-факт (`v_period_progress`); отчёт клиенту и черновик акта (печать в PDF); экспорт CSV.
5. **Финансы и настройки** — счета/поступления (независимое подтверждение), дебиторка, расходы (+ имущество без двойного списания), движения по кассам со сверкой, зарплаты (условия с датой вступления, начисление → утверждение → выплаты/авансы, долг), матрица прав, журнал аудита, нормативы.

## Потоки
- **Заявка**: форма → server action (IP-хэш с солью) → `submit_lead` → `leads` + `lead_events` + `notifications` (всем с `leads.receive`) + `event_outbox` → Realtime показывает тост/счётчик и обновляет список.
- **Допуск проекта**: `launch_project` проверяет 100% подтверждённой оплаты и чек-лист; исключение — только с `projects.launch_override` и причиной (аудит).
- **План**: `generate_period_plan` (черновик, идемпотентно по `(plan_item_id, occurrence_key)`) → `approve_period_plan` → уведомления.
- **Материал**: назначение (`content_assign`: ТЗ+исполнитель+срок обязательны) → переходы `content_transition` (результат для проверки, причина для доработки, ссылка-размещение для «выложено») → проверка размещения администратором.
