# Права доступа

Модель: `roles` + `permissions` + `role_permissions` + `user_roles` + индивидуальные `user_permissions` + членство в проектах (`project_members` и роли в карточке проекта). По умолчанию — запрет. Владелец (`owner`) имеет все права; роль защищена.

Проверка — `public.has_perm(code)` в RLS и во всех RPC. Неактивный/неутверждённый профиль не получает ни одного права.

## Права
Продажи: `leads.view`, `leads.receive`, `leads.manage`, `clients.view`, `clients.manage`, `tariffs.manage`*, `prices.view`*
Производство: `projects.view_all`, `projects.create`, `projects.manage`, `projects.launch_override`*, `content.plan`, `content.manage`, `content.publish`, `tasks.view_all`, `tasks.manage`, `shoots.manage`, `calendar.view_all`
Реклама: `campaigns.view_all`, `campaigns.manage`
Безопасность: `credentials.manage`*, `credentials.reveal`*, `audit.view`*
Финансы: `finance.view`*, `finance.manage`*, `payments.create`*, `payments.confirm`*, `expenses.create`*, `expenses.confirm`*
Зарплаты: `payroll.view`*, `payroll.manage`*, `payroll.approve`*, `payroll.pay`*
Команда: `employees.view`, `employees.invite`, `employees.manage`*, `roles.manage`*
Сайт/отчёты: `cms.manage`, `reports.view`
(* — чувствительное)

## Роли по умолчанию (редактируются в «Роли и права»)
| Роль | Права |
|---|---|
| Управляющий | продажи (все), проекты (все), контент, задачи, съёмки, календарь, сотрудники (просмотр/приглашение), отчёты, цены, внесение поступлений. **Без** подтверждения оплат, зарплат, секретов, матрицы прав |
| Бухгалтер | финансы, поступления (внести/подтвердить), расходы (внести/подтвердить), зарплаты (просмотр/начисление/выплата), цены, отчёты |
| Руководитель отдела | сотрудники (просмотр), все задачи, календарь команды, отчёты |
| Менеджер продаж | свои/свободные заявки, уведомления о заявках, клиенты, цены, создание проектов, внесение поступлений (подтверждает другой) |
| Администратор проекта | публикация, задачи; управление своими проектами (через admin_id) |
| Проект-менеджер | создание проектов, план, контент, задачи, съёмки, календарь |
| Директор по планированию | съёмки, план, календарь, просмотр проектов |
| Креативный директор | план, контент, просмотр проектов, календарь |
| Публикатор | публикация |
| Таргетолог | `campaigns.manage`: свои кампании и проекты, куда назначен (автоматически становится участником проекта своей кампании); видит клиента и контакты этих проектов. Пароли соцсетей — только при отдельном `credentials.reveal`, зарплаты и финансы компании — нет |
| Мобилограф, монтажёр, сторисмейкер, дизайнер, амбассадор | только назначенные материалы/съёмки/задачи и проекты, где они участники |

## Реклама (0014) — область проекта
- Видеть кампанию: `owner_id = я`, или `campaigns.manage` + участник проекта, или управление проектом (`can_manage_project`), или `campaigns.view_all`.
- Менять кампанию, видео, статусы, бюджеты, расходы: `campaigns.manage` + (своя кампания / участник проекта / `campaigns.view_all`) или управление проектом. Статусы и бюджеты — только RPC с историей; журнал расходов — только RPC, без UPDATE/DELETE.
- Клиент проекта: `clients.view`/`clients.manage`/менеджер клиента **или** таргетолог проекта (`is_ad_member`).
- Доступы соцсетей: список и показ — `credentials.reveal` на видимом проекте (+ свежий вход, журнал); добавить/удалить — `credentials.manage` на видимом проекте.
- Проверено `supabase/tests/ads_finance.sql`: чужой таргетолог не видит кампанию, клиента, видео и расходы и не может их добавить.

## Мастер проекта и база клиентов (0018)
- `project_wizard_create` — `projects.create` (+ активный сотрудник). Цена договора > 0 — `prices.view` или `finance.view`; заявленная оплата — `payments.create`; изменение профиля существующего клиента — `clients.manage`. Назначаемые сотрудники должны быть активны.
- `client_lookup` (поиск в мастере) — `projects.create`, `clients.view` или `clients.manage`; anon — нет.
- «База клиентов» — `clients.view`/`clients.manage`; проекты в карточке клиента видны по RLS проектов (`can_view_project`), цены договоров в базе клиентов не показываются.

## Сайт и CMS (0019)
- Опубликованный сайт читают все; правка блоков, порядок, видимость, контакты/SEO, публикация — `cms.manage` (RLS + RPC `publish_site`). Загрузка и замена изображений в bucket `site` — `cms.manage`. Каждая правка черновика и настроек пишется в журнал (`site.block_draft`, `site.settings`).
- Проверено `supabase/tests/smm_kadr_wizard.sql`: мобилограф не создаёт проект и не меняет блоки сайта; anon не меняет блоки.

## Сотрудники (0013)
- Утвердить/заблокировать — только `employee_set_status` с `employees.manage`; нельзя менять свой статус; статус владельца меняет только владелец; без роли утвердить нельзя.
- Карточку сотрудника на утверждении видит тот, у кого `employees.view`; без него — «Недостаточно прав», а не 404.

## Гарантии (проверено `supabase/tests/business_rules.sql`)
- Мобилограф через API не видит `project_contracts` (цены), `payments`, чужие `salary_terms`.
- Нельзя назначить себе owner; нельзя снять/заблокировать единственного owner.
- Продавец не подтверждает собственноручно внесённый платёж (кроме владельца).
- Начисление утверждает не его автор (кроме владельца).
- Экспорт CSV выполняется с правами пользователя (RLS) и логируется в `export_history`.
- Секреты: список — только с `credentials.reveal` на проекте; значение — только `secret_reveal` с входом паролем ≤15 мин назад; каждый просмотр — в `secret_access_log` и `audit_log` без содержимого.
- Зарплатные условия в приглашении и хэш токена скрыты на уровне колонок.
